# 開発順序

## M0: 意味モデルから検査付き出力まで

- Rust core、Python API、schema v1、CadQuery adapter
- 軸平行boxのunion-minus-cuts
- 最終solid数、形状妥当性、keepout、+Zアクセス、部品間干渉
- 成功・失敗作例、単体/統合test、CI、再現手順

M0は初期実装の範囲であり、製造可能性全体を保証する段階ではない。

## M1: 実用筐体の構造と寸法

- 円柱・穴・boss (対応済み)、寸法型と座標変換。面取りはOCCTのedge選択に依存するため見送る
- 部品catalog、基板寸法と出典 (13基板)、支持面への接触指定、コネクタ位置と開口 (対応済み)
- 最終肉厚、接続部断面の保守的な検査 (対応済み)。slendernessは後続
- 閉空洞、印刷姿勢、overhang/bridgeの検査 (対応済み)。slicerでの評価との突合
- STL meshのmanifold性・接続成分・退化三角形検査 (対応済み)

最終形状に対する検査はIRから直接rasterizeしたvoxel上で行い、OCCTのface/edge topologyに依存させない。解像度は`policy.voxel_mm`で指定し、量子化分は失敗側に倒す。overhang/bridgeも同じoccupancyから判定する。

catalogは公式資料が寸法線として与える値だけを持ち、記載のない値は`None`とする。登録済みはRaspberry Pi 8基板とArduino 5基板である。Espressif、Sipeed、Seeedの基板は、寸法図の配布元に到達できないか、寸法線を持つ資料がないため登録していない。コネクタ開口の寸法は、USB・HDMI等の規格書の利用許諾が公開catalogへの転記と両立しないため組み込まない。IR v9の`Connector`が利用者の与えたプラグ寸法と出典を持ち、`connector_fit`が開口・掃引との整合を判定する。詳細は [部品catalog](catalog.md) を参照する。

合格条件: 開口を持つ筐体で、薄肉・折れやすい接続・孤立・支持不能箇所の既知の失敗fixtureを検出し、Tang Nano等の既存ケースへ適用して比較する。

fixtureは `tests/test_enclosure_fixtures.py` が持つ。上面の開いた36×26×14 mmの筐体を基準形状とし、欠陥を1つずつ入れて、不合格となるruleの集合が宣言と完全に一致することを検証する。この比較により、検出漏れと過検出の両方を検出する。

| fixture | 欠陥 | 不合格となるrule |
| --- | --- | --- |
| `baseline` | なし | なし |
| `thin_wall` | 右壁の内側を削り残り1 mm | `final_wall_thickness` |
| `narrow_neck` | 幅1.6 mmの桟だけで左右を繋ぐ | `neck_section` |
| `severed_corner` | 同じスリットを桟を残さず通す | `single_solid`, `neck_section` |
| `cantilever` | 壁から6 mm張り出す棚 | `support_free` |
| `sealed_void` | 塊の内部に外へ通じない空洞 | `closed_cavity` |

`min_neck_mm`は2.0とし、既定の`min_wall_mm` 1.2と分けている。両者が同じ値だと、断面が足りない箇所は必ず肉厚も足りず、2つのruleを区別できない。

既存ケースへは、外部のSTL/STEPへ最終形状のruleを適用する経路 (`typedsolid.external`) で適用した。第三者のファイルはリポジトリに含めず、取得元、commit、sha256と結果だけを [既存ケースとの比較](comparison.md) に記す。Tang Nano 9K用の部品holderは4 ruleすべてに合格し、Tang Nano 20K用のMiSTeryNano筐体は閉じていないmeshのため評価できなかった。

## M2: 組立と保守アクセス

- 工具・ケーブル・コネクタ抜き差しの掃引領域 (対応済み)
- lid取り外し等のassembly state、着脱順序、複数軸のアクセス、keepoutと部品の取付関係 (対応済み)
- 任意ネジ固定 (セルフタップ、熱圧入インサート)、ネジを外す順序、材料・積層方向を含む設計profile (対応済み)
- snap fit (対応済み。矩形断面の片持ち梁)
- backendをworker processへ隔離し、timeout・再開可能な生成を導入 (対応済み)

実装順はworker隔離、分解stepと着脱検査、掃引、profileとネジ固定、snap fitとする。状態ごとに評価が増えるため、打ち切りとcacheを先に入れる。

- **組立状態**: IRに記述した部品位置を組立状態とし、分解手順を順序付きのstepで表す。各stepは部品を軸平行の直線区間を連ねた経路で動かして取り除く。組立順序は分解の逆とする。回転と任意軸の配置変換は扱わない。
- **干渉判定**: 着脱と掃引の干渉はOCCTのBooleanで判定し、clearanceは形状間の最短距離で見る。はめ合い隙間は0.2〜0.3 mm程度でvoxelの既定pitchと同じ桁にあり、量子化を失敗側に倒すと要件を満たす設計も不合格となるためである。既存の`part_interference`と同じ方式になる。
- **掃引**: 現在の`access`を一般化し、box又は軸平行cylinderの断面、方向、距離、必要となる分解stepを持つ`Sweep`とする。
- **数値の出典**: 材料の許容ひずみ、ネジ・インサート寸法は型だけを用意し、値は利用者が与える。catalogと同じく根拠のない既定値を組み込まない。
- **設計profile**: 材料はIRの`Material`とし、部品へ割り当てる。snap fitの許容ひずみを材料に持たせ、M3の材料定数も同じ型へ追加する。印刷機と設計値はPythonのhelperに留め、IRに現れるのはprofileから作った`Policy`、製造案、はめ合い隙間だけである。
- **ネジ固定**: IRの`Fastener`がネジ・インサートの寸法を持ち、`fastener_fit`が貫通穴、座面、かかり長さ、先端の逃げ、bossの肉厚を実形状と照合する。締結力やねじ山の強度はM3の解析で扱う。
- **snap fit**: 矩形断面の片持ち梁に限る。ひずみははりの理論から求め、梁の長さ方向が積層方向と平行でないことを検査する。外すstepではフックをたわませた部品で分解経路を掃引し、たわませないフックが経路を塞ぐこと (保持) も検査する。たわみ量は利用者が宣言する。

## 製造案

組立状態の姿勢と製造時の姿勢を分け、部品ごとに製造法、材料、姿勢の異なる複数の製造案を持たせる。出力の可否は採用した1案で決め、他の案は比較用の結果として示す。

- **段階A** (対応済み): IR v10の製造案。FDMと光造形 (SLA/MSLA) の特性、軸平行24通りの姿勢 (検査は`up`だけを使う)、光造形の排出路 (`resin_drain`) と吸盤 (`resin_suction`)、viewerの製造案の絞り込み。v9の`Policy`の肉厚と姿勢の値は製造案へ昇格する。
- **段階B** (対応済み): IR v11の切削 (3軸) と射出成形。切削は複数の段取りからの工具の到達 (`milling_reach`) と工具の径による削り残し (`milling_corner`)、射出成形は2枚型のundercut (`mold_undercut`) と内接球による厚肉 (`mold_thick_wall`) を検査する。抜き勾配 (`mold_draft`) は軸平行のprimitiveが勾配を持たないため評価しない。治具での固定、側方の型、流動・冷却は扱わない。
- **段階C** (対応済み): IR v12の任意の姿勢 (`turn_deg`の任意角と`tilt_deg`)。傾けた製造案は製造機の座標で格子化し直して判定する。肉厚は距離場の法線方向の弦長で測り、稜線の縁の閾値を除いた。支持は複数層の傾きで判定し、傾いた面の量子化の揺らぎを均す。snap fitの積層方向は製造案ごとに、積層方向との角が45°以上であることを見る。Raspberry Pi 4の筐体の蓋に背面のsnap fitを加え、蓋を50°傾けた製造案で検査を通す。斜めの切削の段取り (3+2軸) は扱わない。

## M3: 解析連携

- **強度と熱** (対応済み): IR v13の材料定数と解析ケース。部品ごとの線形弾性 (等方性、層間の許容応力) と定常熱伝導を、voxelの8節点要素 (非適合モード付き) とマルチグリッド前処理の共役勾配法で解く。外部solverとmesherは使わない。荷重・拘束・発熱・放熱の領域はbox、ネジ固定、keepout、コネクタ開口で指定する。3段の格子で収束を判定し、拘束と荷重の近傍の応力は未評価として残す。引張棒、片持ち梁、1次元の熱伝導で解析解と照合し、Raspberry Pi 4の筐体の底の温度を評価する。
- **内角の丸み** (対応済み): IR v14の`fillet`。軸平行の辺に沿う丸みを、OCCTのedge選択を使わずboxとcylinderのBooleanで表す。部材が最も粗い格子で3 cell以上の厚さを持てば、丸めた内角の応力が収束することをL字で確かめた。厚さ2 mmの筐体の蓋はこの条件を満たさず、収束しない。
- **分布の表示** (対応済み): 応力、層間の引張、変位、温度の表面分布をviewerで色分けする。カラーマップ (連続、発散) と範囲 (上限まで、最小から最大、上限を中点、数値) を切り替え、判定しない近傍に斜線を重ねる。
- **局所的な細分** (対応済み): 強度のケースで、軸方向の厚さと`fillet`の半径から、薄い部材と丸みの周りだけ格子を最大3段 (格子間隔の1/8) まで細かくする。格子は八分木で、隣り合うcellの一辺の比を2以下に揃え、hanging nodeは大きいcellの隅で補間する。厚さ12 mmのL字の半径3 mmの丸み (格子1 mm) と、厚さ4 mmのL字の半径2 mmの丸み (格子0.5 mm) の応力が収束するようになった。熱のケースは細分しない。
- **後続**: 全体が薄い壁の部品 (厚さ2 mmの筐体など) は、細分の範囲が部品全体となり、要素数と計算時間が制約となる。細かい格子の高速化、板の要素、形状に沿う要素、接触、ネジの締結力、放射は未対応である。

## 後続判断

Nix/Docker環境、Windows/macOSのwheel、API拡張は需要とCI費用を見て追加する。可視化は、最終形状の検出箇所の断面図、OCCTで判定するruleの検出箇所、組立状態の投影図、3D viewer (IRのモデルと外部のSTL/STEP、断面の切り口を含む) を実装した。初期対応はLinux x86_64 / CPython 3.12。公開レジストリへのpublishとGitHub Pages公開は初期対応の対象外とする。
